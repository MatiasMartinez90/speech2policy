┌────────────────────────────────────────────────────────────────────────────────┐
│ 1. HOW USERS ARE IDENTIFIED                                                   │
└────────────────────────────────────────────────────────────────────────────────┘

JWT Token (from Cognito)
        ↓
API Gateway Authorizer validates JWT
        ↓
Extracts claims: event.requestContext.authorizer.claims
        ↓
Lambda reads one of:
   - claims.get('email')              ← tutor-handler, progress-handler
   - claims.get('cognito:username')   ← admin-handler, sections-handler, upload-handler
        ↓
Stores as user_id in DynamoDB

┌────────────────────────────────────────────────────────────────────────────────┐
│ 3. USER FIELDS CURRENTLY USED                                                 │
└────────────────────────────────────────────────────────────────────────────────┘

FROM JWT CLAIMS:
  ✓ email              - Email address
  ✓ cognito:username   - Unique Cognito username
  ✓ sub                - Subject (Cognito ID) [NOT USED]
  ✓ aud                - Audience [NOT USED]
  ✓ iss                - Issuer [NOT USED]
  
FROM REQUEST CONTEXT:
  ✓ sourceIp           - Source IP (for anonymous users)
  
FROM COGNITO API:
  ✓ Groups             - List of user groups (e.g., "Admins")

│ 6. DATA STORED BY TABLE                                                       │
└────────────────────────────────────────────────────────────────────────────────┘

TABLE: UserProgress
  PK: USER#{email}
  SK: COURSE#{course_id}
  
  Fields:
    • user_id                           [email]
    • course_id                         [string]
    • current_section                   [int]
    • started_at                        [ISO timestamp]
    • last_activity                     [ISO timestamp]
    • checkpoints_completed             [Map]
      └─ '{section_id}': {
           ├─ score              [Decimal 0-100]
           ├─ passed             [bool]
           ├─ completed_at       [ISO timestamp]
           └─ attempts           [int]
         }
    • total_checkpoints                 [int]
    • checkpoints_passed                [int]
    • hints_used                        [Map]
      └─ '{section_id}': [level_1, level_2, ...]


TABLE: TutorSessions
  PK: SESSION#{session_id}
  SK: TIMESTAMP#{timestamp}
  TTL: 30 days
  
  Fields:
    • user_id                           [email or anon_IP]
    • course_id                         [string]
    • section_id                        [int]
    • message_type                      [question|checkpoint|hint]
    • user_message                      [string]
    • assistant_response                [string, optional]
    • timestamp                         [ISO timestamp]
    • ttl                               [Unix epoch]


TABLE: UserUsage
  PK: user_id (email or anon_IP)
  SK: period (TOTAL | YYYY-MM-DD | YYYY-MM-DD-HH)
  TTL: 7 days (except for TOTAL)
  
  Fields:
    • count                             [int] - Total requests in period
    • question_count                    [int] - /api/tutor/ask
    • checkpoint_count                  [int] - /api/tutor/validate
    • hint_count                        [int] - /api/tutor/hint
    • last_request                      [ISO timestamp]
    • ttl                               [Unix epoch]

┌────────────────────────────────────────────────────────────────────────────────┐
│ 8. KEY INCONSISTENCY TO BE AWARE OF                                           │
└────────────────────────────────────────────────────────────────────────────────┘

CRITICAL DIFFERENCE:

  tutor-handler & progress-handler:
    Use: claims.get('email')
    Example: "user@example.com"
    
  admin-handler, sections-handler, upload-handler:
    Use: claims.get('cognito:username')
    Example: "Google_111137626603562904354"
    
REASON:
  Cognito's admin_list_groups_for_user() API requires the Username field,
  not the email address. The username is stable but email can be missing
  for some OAuth providers.


┌────────────────────────────────────────────────────────────────────────────────┐
│ 9. COMPLETE USER IDENTIFICATION FLOW                                          │
└────────────────────────────────────────────────────────────────────────────────┘

1. User logs in via Google OAuth
   ↓
2. Cognito issues JWT token with claims:
   - email: "user@example.com"
   - cognito:username: "Google_111137626603562904354"
   - sub: "unique-cognito-id"
   ↓
3. Frontend sends request with: Authorization: Bearer <JWT>
   ↓
4. API Gateway Authorizer:
   - Validates JWT signature
   - Extracts claims
   - Adds to event.requestContext.authorizer.claims
   ↓
5. Lambda Handler receives event:
   claims = event.get('requestContext', {}).get('authorizer', {}).get('claims', {})
   ↓
6. Extract user identifier:
   IF tutor/progress handler:
     user_id = claims.get('email')
   ELSE (admin/sections/upload):
     user_id = claims.get('cognito:username')
   ↓
7. Use user_id for:
   - PK in DynamoDB: USER#{user_id}
   - Rate limiting: UserUsage table
   - Session tracking: TutorSessions table
   ↓
8. All subsequent queries use user_id as identifier
